From perceptrons to neural networks

How stacking perceptrons solves XOR — and how generalizing weights, bias, and activation turns that trick into a real neural network.

The problem

A single perceptron separates its inputs with one straight line — a linear decision boundary. That's enough to represent AND, OR, and NAND, but not XOR (⊻, "exclusive or"). The four points in XOR's truth table can't be split into "true" and "false" groups by any single line, no matter how the weights are tuned. This is the classical XOR problem, and it's the reason perceptrons alone are limited — and why networks of them are not.

A quick key to the symbols

Before diving in, here's what the logic symbols mean — they're standard notation, not shorthand invented for this note:

SymbolNameMeaning
∨ORtrue if at least one input is true
∧ANDtrue only if both inputs are true
↑NAND"not AND" — true in every case except both inputs true
⊻XORtrue if exactly one input is true, not both

The trick: compose two simpler perceptrons

Rather than solving XOR directly, build it from two functions that are linearly separable:

  • y₁ = x₁ ∨ x₂ — an OR perceptron. Both weights are 1: it fires whenever at least one input is on.
  • y₂ = x₁ ↑ x₂ — a NAND perceptron. Both weights are −1: it fires in every case except when both inputs are 1.

Unpacking the NAND perceptron step by step

NAND is just AND with the answer flipped — 1 everywhere AND is 0, and 0 only where AND is 1 (both inputs true):

x₁x₂x₁ ∧ x₂ (AND)x₁ ↑ x₂ (NAND)
1110
1001
0101
0001

So in words: NAND fires unless both inputs are on.

Now, how does a perceptron with weights −1 and −1 actually produce this? A perceptron computes a weighted sum of its inputs, then checks whether that sum clears a threshold. With both weights set to −1, the weighted sum is:

−1·x₁ + −1·x₂ = −x₁ − x₂

Plugging in all four input pairs:

x₁x₂−x₁ − x₂
11−2
10−1
01−1
000

The perceptron's firing rule is: output 1 if the sum is −1 or higher; output 0 if it's lower than −1. Checking each row against that rule reproduces NAND exactly — the sum only drops below −1 when both inputs are on.

Plain-language intuition: each input being "on" (1) drags the sum down by 1, because its weight is −1. A threshold of −1 means "you're allowed to drag the sum down once, but not twice." One input on is fine — the neuron still fires. But if both inputs are on, the sum drops too far and the neuron shuts off. That's exactly "fires unless both are on" — NAND.

Put in words, these two hidden neurons together contain everything XOR needs:

  • XOR is true when at least one input is 1 — that's exactly what y₁ (OR) checks.
  • XOR is false only when both inputs are 1 — that's exactly what y₂ (NAND) rules out.

So XOR is true precisely when both conditions hold at once:
x₁ ⊻ x₂ = y₁ ∧ y₂

Checking it against the truth table

x₁x₂y₁ = x₁∨x₂y₂ = x₁↑x₂y₁ ∧ y₂ (= XOR)
11100
10111
01111
00010

Every row lines up with XOR: true only when the two inputs differ.

The network

Wiring this up means feeding the outputs of two perceptrons (y₁, y₂) into a third one that computes their AND. Three layers of neurons, each layer feeding the next:

Input — raw variables x₁, x₂
Hidden — intermediate neurons (not inputs or the final answer)
Output — the network's final answer

Input layer: x₁ and x₂, the raw variables. Hidden layer: y₁ and y₂, neurons that are neither inputs nor the requested output — they compute intermediate features (OR and NAND) that turn out to be exactly the stepping stones XOR needs. Output layer: a single neuron computing the AND of the hidden layer, which is XOR.

Why this matters

This is the core argument for why neural networks stack layers at all. A lone perceptron is stuck with linearly separable functions. But by letting one layer's outputs become the next layer's inputs, the network as a whole can represent functions — like XOR — that no single perceptron could learn on its own.

Neural network: a network of artificial neurons in which neuron outputs are inputs into other neurons.

The "hidden" in hidden layer just means these neurons aren't part of the problem's stated input or output — y₁ and y₂ are internal representations, built (here, by hand; in practice, learned) to make the final classification possible.

Generalizing the perceptron

Everything above used perceptrons with fixed integer weights (1, −1) and an implicit threshold. The next step is to generalize that idea into something closer to what real neural networks use.

A generalized neuron allows n arbitrary decimal inputs (often scaled between 0 and 1) and computes:

f(w₁·x₁ + w₂·x₂ + … + wₙ·xₙ − b)

Two new pieces appear here that weren't explicit in the XOR network:

  • Bias (b): a constant subtracted from the weighted sum. It shifts the threshold at which the neuron "turns on" — equivalent to the fixed thresholds implied by the OR/NAND perceptrons earlier, but now an explicit, tunable number rather than something baked into the wiring.
  • Activation function (f): a function applied to the weighted sum before it becomes the neuron's output. In the OR/NAND/AND perceptrons above, this was effectively a hard step (fire or don't fire). A generalized neuron can use other, smoother functions instead.

A smoother activation function: the logistic function

A hard step function is awkward to work with mathematically — it isn't differentiable at the threshold, which matters once networks are trained by gradient-based methods. A common substitute is the logistic function (a sigmoid):

f(x) = 1 / (1 + e⁻ˣ)

Rather than jumping abruptly from 0 to 1, it eases between them: strongly negative inputs map close to 0, strongly positive inputs map close to 1, and inputs near 0 map close to 0.5, with a smooth S-shaped curve in between.

Swapping the hard threshold for a smooth activation function like this one is what turns the toy, hand-built XOR network above into the kind of building block real neural networks are made of: layers of neurons with tunable weights and biases, connected by differentiable activation functions, ready to be trained rather than manually wired.
